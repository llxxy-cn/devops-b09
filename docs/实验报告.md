## E6 自动构建与验证（分工2）

E6 服务镜像构建证据保存在 `work/build-e6-241880481-03`：
镜像构建退出码为0，服务内原有24项单元测试全部通过。
新增的云端入口与 Buildx 透传测试共12项，全部通过。

E6 前两次运行保留为基础设施诊断：

- `work/e6-own-241880481-01` 使用服务容器内默认 builder，访问
  `registry-1.docker.io` 超时，第一轮分类为 `INFRASTRUCTURE`。
- `work/e6-own-241880481-02` 已选中 `e5-241880585`，但直接只读挂载
  Buildx 元数据时，Buildx 更新 `activity` 文件失败，第一轮分类为
  `OTHER_BUILD_ERROR`。

修复后，宿主机 `~/.docker/buildx` 仅只读挂载到暂存路径，再复制到一次性
服务容器内可写的 `/tmp/.docker/buildx`。该处理未挂载
`~/.docker/config.json`，未修改宿主机 Docker daemon，也未修改候选
Dockerfile、固定基础镜像摘要、候选哈希或自动构建算法。

正式成功目录为 `work/e6-own-241880481-03`。第一轮真实执行 `RUN make`，
以退出码127复现 `/bin/sh: 1: make: not found`，分类为 `MISSING_MAKE`；
第二轮使用 `work/candidate/Dockerfile` 构建成功，构建退出码为0。

运行验证使用第二轮生成的同一完整镜像 ID：
`sha256:b4435be7a948f51cf6a4dfae899c735defb78c0fb154ac87216e1042a1f54796`。
验证命令包含 `--network none`，程序退出码为0，实际输出为
`hello E3\n`，`output_matches=true`，E6 总状态为 `SUCCEEDED`。

证据校验命令：

```bash
python3 scripts/verify_e6_b_evidence.py \
  --run-dir work/e6-own-241880481-03/evidence
```

校验器退出码为0且 `passed=true`。本次 trace ID 为
