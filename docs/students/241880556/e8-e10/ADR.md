# ADR：B3 采用“全部检查通过后写回”的候选验收策略

## 决定

候选 Patch 在隔离副本中依次执行应用检查、构建、程序测试、头文件
变化后的增量构建和依赖复扫。只有全部检查通过时才把 Makefile 写回
原项目；任一步失败均拒绝候选，并验证原 Makefile 字节不变。

对组内交付物增加输入门禁：项目必须保留 `.git`，工作区必须干净，
报告提交必须等于项目 HEAD，修改计划中的风格必须与项目风格一致。

## 理由

仅检查 Patch 能否应用不能证明候选可构建、行为正确或修复了增量构建。
先在隔离副本完成全部验证，可避免半完成修改污染原项目。把报告提交、
计划和 Git 状态纳入门禁，可以阻止过期或错配材料进入验证阶段。

## 个人实现

- 在 `test_profile.py` 中增加编译失败回滚测试；
- 新增 `validate_b2_handoff.py`，执行 direct、macro、mixed 的接受验证，
  以及测试失败、编译失败和无效 Patch 的拒绝验证；
- 对接受结果调用真实 BuildChecker，要求复扫后不存在 `MISSING`。

## 代价与边界

每个候选需要额外构建、运行和复扫，执行成本高于单纯的
`git apply --check`。当前实现针对课程限定的 GCC、本地头文件和显式
Make 规则，不声称支持任意 Makefile 或其他构建系统。
