# ADR：B1 固定输入、候选隔离与全门禁接受

## 决定

1. E8 使用课程固定 C/Make 项目建立可交付基线，报告绑定样例项目完整 SHA。
2. E9 对 direct、macro、mixed 分别建立独立项目；候选生成和应用检查不写回输入。
3. E10 只在全部检查通过时把 sandbox 中的 Makefile 写回原项目；任何拒绝都要求
   `rollback=true`、`source_unchanged=true` 并核对原字节。
4. 质量判定同时包含 Patch 可应用、全量构建、程序输出、头文件变化后重编译、
   GCC 扫描和真实 BuildChecker 复扫，不能用“首次构建成功”替代增量正确性。

## 理由

固定输入使 B1、B2、B3 可以在组内复现和交接，不依赖 A 组服务进度。隔离候选
和输入可以清楚区分“生成”“验证”“接受”，并为拒绝路径提供逐字节回滚证据。
只修复 MISSING、保留 REDUNDANT，符合本次课程策略和既有接口约定。

## 代价与限制

当前实现只覆盖受限的显式 Make 规则、有限变量展开和项目内头文件。共享变量的
跨目标影响、复杂隐式规则及真实 A 组报告格式仍需后续扩展。E9/E10 本次运行在
Docker Desktop 的 Linux/amd64 引擎，不等同于课程服务器机器证明；跨组联调属于
E11—E12，不纳入本 ADR 的完成范围。
